# AI Phishing Detector

An AI-based phishing detection tool that analyzes URLs to identify potential phishing attempts. It combines a machine learning model with rule-based security checks and returns a verdict (`Legitimate`, `Suspicious` or `Phishing`) together with a risk score from 0 to 100.

## Features

- **ML-powered classification**: a Scikit-learn Random Forest trained on 10 URL-based features of the UCI Phishing Websites dataset (90.7% accuracy on the test set)
- **Dual-signal verdict**: combines the ML phishing probability with heuristic alerts, so neither signal can override the other on its own
- **Domain whitelist**: major brands (Google, PayPal, GitHub, etc.) are cleared instantly to avoid false positives
- **Typosquatting detection**: RapidFuzz (Levenshtein distance + partial matching) catches look-alike domains such as `paypa1.com`, `gooogle.com` or `netflix-billing-update.com`
- **Unicode homograph detection**: flags IDN attacks that use visually identical characters (e.g. Cyrillic `а` vs Latin `a`)
- **Shannon entropy scoring**: flags random-looking domains often generated by phishing kits
- **Phishing keyword scanning**: detects words like `login`, `verify`, `bank` or `secure` using word-boundary matching
- **IP address detection**: flags URLs that use a raw IP instead of a domain name
- **Subdomain depth check**: detects suspiciously long subdomain chains
- **HTTPS validation**: flags URLs that do not use a secure protocol
- **URL trick detection**: URL shorteners, `@` symbols hiding the real domain, hidden `//` redirects and non-standard ports
- **Risk score (0–100)**: a quantified threat level consistent with the verdict (Legitimate 0–29, Suspicious 30–69, Phishing 70–100)
- **REST API with CORS**: clean JSON responses, easy to connect to any frontend
- **Graceful fallback**: the API still works with heuristics only if the model file is missing

## Tech Stack

- **Backend:** Python, Flask, Flask-CORS
- **Machine learning:** Scikit-learn, Pandas, NumPy
- **URL analysis:** tldextract, RapidFuzz
- **Frontend:** HTML, CSS, JavaScript

## Getting Started

### 1. Install dependencies

```bash
pip install -r requirements.txt
```

### 2. (Optional) Retrain the model

```bash
python model/train_model.py
```

### 3. Start the API

```bash
python backend/app.py
```

The API runs at `http://127.0.0.1:5000`.

### 4. Open the frontend

Open `frontend/index.html` in your browser, paste a URL and click scan.

## API Usage

**POST** `/predict`

Request:

```json
{ "url": "http://paypa1-login-verify.com/account" }
```

Response (shortened):

```json
{
  "url": "http://paypa1-login-verify.com/account",
  "prediction": "Phishing",
  "risk_score": 44,
  "alerts": [
    "Possible typosquatting of 'paypal' (similarity 90.9%)",
    "High entropy domain detected (entropy: 3.7216)",
    "Suspicious phishing keywords found in URL",
    "URL does not use HTTPS"
  ],
  "details": { "uses_https": false, "has_ip_address": false, "...": "..." }
}
```

## How the Model Works

The model is trained on the [UCI Phishing Websites dataset](https://archive.ics.uci.edu/dataset/327/phishing+websites) (11,055 websites). This dataset has 30 features, but many of them need the page HTML, WHOIS records or traffic statistics, which are not available when the API only receives a URL.

The model therefore uses only the **10 features that can be computed from the URL itself**, with the same encoding as the dataset (`1` legitimate, `0` suspicious, `-1` phishing):

| Feature | What it checks |
|---|---|
| `having_IP_Address` | IP address instead of a domain name |
| `URL_Length` | Long URLs (> 75 characters) |
| `Shortining_Service` | URL shorteners (bit.ly, tinyurl…) |
| `having_At_Symbol` | `@` symbol in the URL |
| `double_slash_redirecting` | `//` after the protocol |
| `Prefix_Suffix` | `-` in the domain name |
| `having_Sub_Domain` | Number of subdomains |
| `SSLfinal_State` | HTTPS usage |
| `port` | Non-standard port |
| `HTTPS_token` | "https" written inside the domain name |

**Results on the test set (20% of the data):** 90.7% accuracy, 92% precision and 86% recall on phishing sites.

### Limitations

- The SSL feature is approximated from the URL scheme: the certificate itself is not verified.
- The dataset dates from 2015, so recent phishing techniques may be less well represented.
- Because the model only sees the URL structure, its prediction is used as one signal among others, combined with the heuristic checks.
